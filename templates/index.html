Anna University Regulation 2025 | Viva Voce & Academic Guide

Data Structures (CS3301 / R2025)

Comprehensive academic explanations, time and space complexity analyses, mathematical formulas, and prepared viva questions designed for high scoring in college practical and project evaluations.

1. What is Hashing and why is it used for duplicate detection?

Hashing is a technique to convert a large or variable-length key (such as a composite student or customer record string) into a fixed-size integer value using a mathematical hash function. This integer is mapped to an index in a hash table.

For duplicate detection, naive comparison requires comparing every record with every other record, resulting in O(n²) time complexity. Sorting-based detection takes O(n log n) time. With hashing, we compute the record's hash key and look up its bucket in O(1) average time, reducing total processing time to O(n).

2. What is a Hash Table and what is Load Factor (α)?

A Hash Table is a data structure that implements an associative array abstract data type, mapping keys to values using a hash function to compute an index into an array of buckets.

The Load Factor (α) is defined mathematically as:

α = N / M

where N is the number of elements inserted and M is the capacity (number of buckets). When α exceeds a threshold (typically 0.75), performance degrades, triggering dynamic rehashing to a larger prime table capacity.

3. What is a Hash Collision and how does Separate Chaining resolve it?

A Hash Collision occurs when two distinct keys k₁ ≠ k₂ produce the exact same bucket index: H(k₁) % M == H(k₂) % M. By the Pigeonhole Principle, collisions are inevitable whenever the key universe is larger than table capacity M.

In Separate Chaining, each bucket in the hash table points to the head of a linked list (or chain) of entries that hash to that same index. When a new key hashes to an occupied bucket, we traverse the chain to check if an identical key already exists (detecting a duplicate); if not, the new node is appended in O(1) time at the head.

4. Which Hash Functions are implemented in this project?
  • Polynomial Rolling Hash: H(s) = (∑ s[i] · pⁱ) mod 2³² with prime base p = 31. Ideal for string keys and compiler symbol tables.
  • DJB2 (Dan Bernstein): hash = ((hash << 5) + hash) + char = hash * 33 + char starting from initial seed 5381.
  • FNV-1a (32-bit): hash = (hash ⊕ char) · FNV_PRIME starting from offset basis 2166136261.
5. How does the system handle records with Different Schemas?

The system separates parsing from matching using an academic 4-stage pipeline:

  1. Parser Layer: Extracts raw dictionaries from CSV, TSV, XLSX, XLS, JSON, JSONL, PDF, DOCX, and TXT.
  2. FieldMapper: Unifies heterogeneous column names (e.g. student_name, full_name, customer_name → canonical name).
  3. RecordNormalizer: Normalizes case, removes honorifics, collapses whitespace, canonicalizes phone numbers and emails, and creates an order-independent composite key by sorting canonical field keys alphabetically.
  4. Multi-Tier Hashing: Primary table catches exact duplicates; secondary hash tables on strong identifiers (email, phone, student ID) catch partial duplicates across heterogeneous schemas.
